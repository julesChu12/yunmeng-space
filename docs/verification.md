## 移动端复验与预览更新缺陷修复

上一轮验收不充分：截图对应的构建产物正确，但长期运行的预览服务会继续使用已缓存的旧模板。之后修改客户端脚本或样式触发重建，会把旧版 `.hotspot` 标记重新写回 HTML；新版样式不再包含该类规则，导致两个“＋”出现在手机图片下方。先前的截图和状态检查不足以证明当前服务输出正确。

本次在实际运行的 4173 服务上复现：两个旧按钮均为 `position: static`，缺陷截图为 `previews/mobile-broken-before.png`。

修复与验证：

- 开发服务每次用独立构建进程读取模板，避免复用模块缓存。已重启原项目的 4173 预览服务。
- 新增 `npm run test:dev`：在临时副本中启动真实服务、修改模板，再读取 HTTP 页面。修复前出现“服务提示更新但页面仍为旧模板”的失败，修复后通过。
- 在当前服务继续修改模板并刷新，确认新断行结构生效、旧 `.hotspot` 数量为 0。
- 手机首屏改为介绍、图片、批注、浏览入口的顺序；375px 下图片顶部从约 417px 提前到约 296px，批注区域底部从约 928px 提前到约 711px。
- 手机正文放大，修正关于设计师、手记卡片和文章标题的断词；玄关图改用约 164 KB 的 JPEG，保留原始 PNG。
- 实际查看 320、375、390、430px 首屏截图；逐屏查看案例、关于设计师、服务、手记、FAQ 和咨询区域，以及一篇文章、一条案例详情。
- 验证手机菜单、批注切换、服务展开、咨询弹窗关闭及滚动后的提交按钮位置。
- 390px 完整首页中所有配图加载成功；各检查宽度无横向溢出。1440px 桌面批注可见并可切换，未恢复旧十字。
- 静态检查仍通过：8 个页面、143 处本地引用。没有新增第三方依赖。
